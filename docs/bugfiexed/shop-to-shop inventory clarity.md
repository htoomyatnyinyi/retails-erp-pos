akhayar-pos-app တွင် **Shop-to-shop inventory transfer (ဆိုင်တစ်ဆိုင်မှ တစ်ဆိုင်သို့ ပစ္စည်းလွှဲပြောင်းခြင်း)** လုပ်ဆောင်ချက်ကို စစ်ဆေးပြီး အဓိက အမှားများနှင့် UI clarity (မြင်ကွင်းရှင်းလင်းမှု) များကို အောက်ပါအတိုင်း ဖြေရှင်းပြီးစီးသွားပါပြီ -

---

### 🛠 ပြင်ဆင်ပြီးစီးသွားသော အဓိက အချက်များ (Bugs Fixed)

1. **စတော့ရှယ်ယာ တိုက်ရိုက်မလှုပ်ရှားခြင်းကို ဖြေရှင်းခြင်း:**

- ယခင်က အွန်လိုင်းမှ လွှဲပြောင်းလျှင် PENDING request သာ ဖန်တီးပြီး စတော့အရေအတွက် တကယ်မလျော့/မတိုး ဖြစ်နေခဲ့ခြင်းကို ပြင်ဆင်လိုက်ပါပြီ။
- ယခုအခါ အွန်လိုင်းရော အော့ဖ်လိုင်းပါ **local OUT နှင့် IN** ကို အမြဲမှတ်သားပေးပြီး sync လုပ်သည့်အခါ `TRANSFER_OUT` / `TRANSFER_IN` သို့ တိုက်ရိုက်ရောက်ရှိသွားမည် ဖြစ်ပါသည်။

2. **Destination Store တွင် Inventory Row မရှိသေးလျှင် စတော့မဝင်ခြင်းကို ဖြေရှင်းခြင်း:**

- ပစ္စည်းလက်ခံမည့် ဆိုင်ခွဲတွင် ယခင်က စာရင်းဇယား (row) မရှိသေးပါက စတော့ဝင်ရန် ခက်ခဲနေရာမှ ယခုအခါ လွှဲပြောင်းလိုက်သည်နှင့် လိုအပ်သော row အသစ်ကို အလိုအလျောက် ဖန်တီးပေးပြီး စတော့ဝင်ရောက်စေမည် ဖြစ်ပါသည်။

3. **ပစ္စည်းလက်ကျန် စစ်ဆေးခြင်း:**

- လက်ရှိရှိနေသော ပမာណထက် ပိုလွှဲ၍မရအောင် အရေအတွက် (Quantity) ကို အမြဲစစ်ဆေးပေးမည့် စနစ်ထည့်သွင်းထားပါသည်။

---

### 👁 ပိုမိုရှင်းလင်းလာသော User Interface (Clarity)

- **Modes များကို ခွဲခြားပေးထားခြင်း:** **Adjust stock** (စတော့ညှိခြင်း) နှင့် **Store transfer** (ဆိုင်ချင်းလွှဲပြောင်းခြင်း) ဆိုပြီး သီးခြားစီ ရှင်းလင်းစွာ ခွဲခြားပေးထားပါသည်။
- **Transfer UI:** လွှဲပြောင်းသည့်အခါ **From -> To** (ဘယ်ဆိုင်မှ ဘယ်ဆိုင်သို့) ဆိုသည်ကို သိသာစေရန် destination picker နှင့် “Transfer to [Store Name]” ကဲ့သို့သော CTA ခလုတ်များကို ထည့်သွင်းပေးထားပါသည်။
- **Success Messages:** အောင်မြင်စွာ လွှဲပြောင်းပြီးပါက ဆိုင်နှစ်ဆိုင်လုံး၏ အမည်များကို အတိအကျ ဖော်ပြပေးမည်ဖြစ်ပါသည်။
- **Movements List:** မှတ်တမ်းများတွင် ကြမ်းတမ်းနေသော `IN — STOCK_TRANSFER` အစား ဆိုင်အမည်ပါဝင်သည့် **“Transfer in/out”** ဟု ရှင်းလင်းစွာ ပြသပေးမည် ဖြစ်ပါသည်။
